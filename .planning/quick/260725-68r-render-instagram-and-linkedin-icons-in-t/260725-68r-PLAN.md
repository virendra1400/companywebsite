<design_decisions>
- **Unknown URLs are skipped, not given a generic glyph.** The feature scope is Instagram + LinkedIn brand icons. Rendering an unlabeled external-link glyph for arbitrary `sameAs` entries adds a vague, low-value affordance. Skipping is the graceful, honest behavior. Upgrade path: add another `{ match, platform, label, Icon }` entry + icon component when a new platform is wanted.
- **aria-label = the platform brand name** ("Instagram", "LinkedIn"). Brand names are proper nouns that do not translate, so a static string is locale-neutral and fully accessible (screen reader announces "Instagram, link"). This intentionally avoids adding next-intl keys across locale catalogs for a quick task — consistent with the English-first / translation-deferred posture. Upgrade path: introduce a `footer` namespace with a "Follow us on {platform}" key if translated phrasing is later wanted.
- **Scheme guard at the trust boundary:** the resolver only accepts URLs beginning with `https://` (or `http://`) so a mistyped/hostile `javascript:` value that merely contains a platform substring can never become a rendered href.
</design_decisions>
