<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Server Action | Untrusted form payload (incl. Turnstile token) crosses into the server |
| Server Action → Resend / Cloudflare / CRM | Server-side outbound calls carrying secrets + user data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Denial of Service / Repudiation | submitContactForm public entry | high | mitigate | Three-layer defense composed in order: honeypot silent-success branch + in-memory rate limit (3/60s) + Turnstile siteverify |
| T-04-02 | Spoofing | Turnstile token | high | mitigate | Server-side `siteverify` against Cloudflare with the secret key; tokens are single-use and expire (~300s), never trusted on presence alone |
| T-04-03 | Tampering | resend.emails.send from/to headers | high | mitigate | `from`/`to` are fixed server-side constants; user data appears only in the subject/body, never interpolated into address headers |
| T-04-04 | Information Disclosure | secret env vars | high | mitigate | `RESEND_API_KEY`, `TURNSTILE_SECRET_KEY`, `CRM_WEBHOOK_URL` are server-only; never `NEXT_PUBLIC_`-prefixed |
| T-04-05 | Tampering / Elevation of Privilege | CRM_WEBHOOK_URL outbound target | medium | mitigate | Deploy-time env var set by the project owner only; never influenced by request data (SSRF-adjacent note for the future real CRM integration) |
| T-04-SC | Tampering | npm installs (resend, react-email, @marsidev/react-turnstile) | high | mitigate | RESEARCH Package Legitimacy Audit approved all three with direct `npm view` evidence; run slopcheck on install; `@react-email/components` excluded (deprecated) |
</threat_model>
