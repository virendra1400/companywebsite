<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser → client components (switcher/nav) | Client-side locale navigation; no privileged data crosses here. |
| SSR page → Payload Local API (getHomeContent) | Server-side read of localized content; draft/unpublished content must not leak. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10 | Information Disclosure | page.tsx rendering unpublished/draft locale content | mitigate | getHomeContent reads via the server-side Local API using published content only; the fallback path renders published English, never a draft — no draft leaks to the public HTML (Task 3). |
| T-01-11 | Tampering | client-side dir/locale manipulation | accept | dir is server-set (Plan 01) and re-derived per request; a client tampering with its own DOM only affects that session, no server trust depends on it. |
| T-01-12 | Spoofing | open-redirect via switcher target path | mitigate | router.replace uses the locale-agnostic usePathname value + the fixed 4-locale allowlist; no user-supplied absolute URL is used as a redirect target (Task 2). |
</threat_model>
