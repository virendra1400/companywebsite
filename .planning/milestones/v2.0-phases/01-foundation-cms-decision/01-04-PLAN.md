<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → Vercel preview (site + /admin) | The deployed app exposes both the public site and the Payload admin auth surface. |
| Vercel build/runtime → EU Postgres + EU S3 | Secrets cross via Vercel encrypted env; must never be committed to VCS. |
| public internet → EU object-storage bucket | Uploaded media served via CDN; bucket must not be world-writable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-13 | Information Disclosure | secrets in vercel.json / repo | mitigate | All secrets in Vercel encrypted env only; acceptance greps vercel.json/README for committed secrets; .env.example placeholders only (Task 1). |
| T-01-14 | Spoofing | admin login exposed on public preview URL | mitigate | Payload auth (cookie JWT, maxLoginAttempts/lockTime) guards /admin; strong first-user password via onboarding (inherited from Plan 02 T-01-04); preview URL is not indexed. |
| T-01-15 | Tampering | world-writable object-storage bucket | mitigate | Bucket credentials are write-scoped to the single EU bucket (user_setup); public access is read-only via CDN, not write (Plan 02 T-01-06 mime restriction still applies at the Payload upload layer). |
| T-01-16 | Information Disclosure | CLOUD Act exposure of EU-hosted data | transfer | Region pinned to EU; residual legal exposure remains a business/legal DPA/SCC decision (Pitfall 5) — flagged, not engineering-resolvable. |
</threat_model>
