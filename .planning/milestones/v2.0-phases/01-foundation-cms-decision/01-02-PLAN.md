<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous internet → /admin auth | Login attempts against the Payload admin panel. |
| authenticated editor → collection/field access | An editor must not escalate to admin or edit Users. |
| app → external services (Postgres, S3) | Secrets (DATABASE_URL, PAYLOAD_SECRET, S3 creds) cross this boundary; must live only in env, never in code/VCS. |
| anonymous internet → object-storage bucket | Media bucket must not be world-writable and must not accept arbitrary file types. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Spoofing | Payload admin first-user credentials | mitigate | Use Payload's own first-user onboarding for a strong password; never seed a default/known password in any script (Security Domain). |
| T-01-05 | Elevation of Privilege | Users.roles field | mitigate | `roles` field `access.update` returns true only for admin; editor role cannot self-promote (Task 2). |
| T-01-06 | Tampering | Media upload accepting arbitrary/executable files | mitigate | `mimeTypes: ['image/*','application/pdf']` on the Media collection, nothing broader (Task 2). |
| T-01-07 | Information Disclosure | secrets in code/VCS | mitigate | All secrets via `process.env.*`; `.env.example` carries placeholders only; real values entered via user_setup / Vercel encrypted env (Plan 04). Task 1 acceptance greps for no real secrets. |
| T-01-08 | Information Disclosure | public exposure of unpublished/draft localized content | mitigate | All collection/global `access.read` default to authenticated-admin for management APIs; public site reads go through the server-side getPayload Local API, not a world-readable REST/GraphQL write surface (no public write use case in Phase 1). |
| T-01-09 | Information Disclosure | US CLOUD Act exposure of EU-region data | transfer | EU region satisfies residency; residual legal exposure flagged to business/legal owner for DPA/SCC sign-off (Pitfall 5) — not an engineering fix, does not block this plan. |
</threat_model>
