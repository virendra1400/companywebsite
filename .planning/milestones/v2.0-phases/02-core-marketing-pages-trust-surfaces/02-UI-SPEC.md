## Spacing Scale (inherited, unchanged)

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (badge padding, form field gap) |
| md | 16px | Default element spacing, mobile container padding, card internal padding (mobile) |
| lg | 24px | Section padding, tablet container padding, card internal padding (desktop), grid gaps |
| xl | 32px | Layout gaps between blocks on mobile |
| 2xl | 48px | **Section vertical padding (mobile)** — every block wraps in a section with `py-2xl` on mobile |
| 3xl | 64px | **Section vertical padding (desktop, `md:py-3xl`)** — every block on tablet+; also hero vertical padding (unchanged from Phase 1) |

**Section rhythm rule (new, Phase 2):** every block-level `<section>` uses `py-2xl md:py-3xl` and alternates background between `bg-white` (dominant) and `bg-neutral-100` (secondary) as pages scroll, giving the "rich scrolling trust story" visual cadence the homepage direction calls for, without inventing new spacing values. Two consecutive blocks never share the same background — alternation is the block-ordering rule, not a per-block toggle field.

**Container/breakpoints:** unchanged from Phase 1 — max-width 1280px, logical `padding-inline` (16/24/32px), Tailwind default breakpoints (`sm` 640 / `md` 768 / `lg` 1024 / `xl` 1280 / `2xl` 1536).

**Exceptions:** none beyond Phase 1's 44×44px icon-touch-target rule, which applies again to the WhatsApp icon-link and PDF-download icon-links on mobile.

## RTL & Locale Contract — Phase 2 Extensions

Everything in Phase 1's RTL contract applies unchanged (logical properties only, `dir` server-set, Western numerals for `ar`, `<bdi>`/`dir="ltr"` spans for mixed BiDi content). Two additions specific to Phase 2 content types:

| Concern | Rule |
|---|---|
| **Geographic maps do not mirror** | Add to Phase 1's "do NOT mirror" list: the Export Track Record world-map SVG renders identically in `ltr` and `rtl` — geography is not directional. Only the stat-tile list and any text labels around the map use logical properties/reorder normally. |
| **Incoterms/technical abbreviations in mixed content** | Any Latin abbreviation (FOB, CIF, ISO, HACCP, FSSAI, APEDA) appearing inside Arabic sentence copy (RichText blocks) wraps in `<bdi>` or an explicit `dir="ltr"` inline span — this is the pattern Phase 1 flagged as "not needed yet, must be documented now" (01-UI-SPEC.md RTL contract row "Mixed BiDi content"); Phase 2 is where it's actually exercised. |
| **Contact form field order** | Two-column desktop layout (info column + form column) uses normal DOM order + logical flex — info renders inline-start, form inline-end in LTR; automatically swaps in RTL via `dir`, no manual reordering. Mobile: single column, same DOM order (info, then form), stacked. |
| **CertCard grid / FeatureGrid / MediaGallery** | CSS Grid auto-flows correctly per `dir` with no extra rules — confirmed pattern from Phase 1, no new RTL work needed for grid-based blocks. |

## Block Library (Payload page-builder blocks — D-01)

Every block below is a Payload block definition rendered inside the existing `[locale]` layout (Phase 1 chrome wraps every page automatically — no block re-implements header/footer). Fields marked "localized" follow the Phase 1 field-level-localization + EN-fallback pattern (`localized: true`, `fallback: true`). All image/media fields reference the existing `Media` collection.

### 1. Hero (generalize existing `src/components/Hero.tsx`)

Extend, don't replace, the Phase 1 Hero component with two new optional fields and a `variant` prop.

| Field | Type | Notes |
|---|---|---|
| `variant` | `full \| compact` (not localized — content-authoring choice) | `full` = homepage only (existing 70dvh min-height). `compact` = every interior page (About, Contact, Certifications, Manufacturing, Export, Company) — min-height `320px` mobile / `400px` desktop, same photography+gradient+headline pattern, smaller footprint since interior pages have more content below. |
| `eyebrow` | text, localized, optional | Label token, `tracking-wide`, e.g. "ISO · HACCP · APEDA CERTIFIED" — renders above the headline. Homepage-only in practice but the field is available on every Hero instance. |
| `headline` | text, localized | Display token — unchanged |
| `subhead` | richtext/text, localized, optional | Body token — unchanged |
| `primaryCta` | group (label + href), localized label | Reuses `PrimaryButton` — unchanged |
| `secondaryCta` | group (label + href), localized label, optional | **New.** Outline/ghost button variant (shadcn Button `variant="outline"`, white border on dark hero background), positioned inline-end of the primary CTA on desktop, stacked below on mobile. Used on homepage for the WhatsApp CTA ("Chat on WhatsApp"). |

Responsive: unchanged flex-column-centered pattern from Phase 1; `compact` variant drops the `min-h-[70dvh]` to `min-h-[320px] md:min-h-[400px]` and headline uses `max-w-2xl` still but the section itself doesn't need to fill the viewport.

### 2. RichText

CMS Lexical rich text (existing Payload feature, no new package). Container: `max-w-[720px] mx-auto` (approx. 65-75ch measure for readability) inside the standard page container. Body token for paragraphs; any headings authored within rich text render as Heading token (`<h2>`/`<h3>` both map to the single Heading size — no visual sub-heading tier, per the 4-size discipline). Used for: About story, Company/Compliance narrative (leadership intro, IEC/registration/logistics copy), Manufacturing process overview, Certifications page intro.

### 3. FeatureGrid (value props / leadership variant)

| Field | Type | Notes |
|---|---|---|
| `sectionTitle` | text, localized, optional | Heading token |
| `variant` | `icon \| photo` | `icon` = value props (lucide icon + title + body). `photo` = leadership bios (96px circular photo + title + body). One block type, one variant flag — not two separate blocks. |
| `items[]` | array (icon/photo, title, body) | 3-4 items typical |

Layout: 1 column mobile → 2 columns `md:` → 3-4 columns `lg:` (`grid-cols-1 md:grid-cols-2 lg:grid-cols-4` for value props with 4 items; leadership uses `lg:grid-cols-3` if 3 bios — item count drives column count, planner's discretion at build time, cap at 4 columns). Gap: `gap-lg`. Each tile: shadcn `Card` primitive, `p-lg`, icon/photo top, Body-600 title, Body-400 description below.

### 4. StatsBand

| Field | Type | Notes |
|---|---|---|
| `sectionTitle` | text, localized, optional |
| `stats[]` | array (number/value text, unit/suffix text, label text) | e.g. `{ value: "15+", label: "Years Exporting" }`, `{ value: "40+", label: "Countries Served" }`, `{ value: "500+", label: "Container Shipments" }` |

Layout: horizontal row wrapping to grid on mobile — `grid grid-cols-2 md:grid-cols-4 gap-lg` (2 up on phone, up to 4 up on desktop). Each tile: Display-token number (`text-primary-700`), Label-token caption below (`text-neutral-600`), centered, no card border (StatsBand reads as a lightweight band, not boxed cards — visually distinct from FeatureGrid/CertCard so the page doesn't feel like an unbroken wall of cards).

### 5. CertStrip (homepage teaser) + CertCard (full Certifications page)

**CertCard** is the single reusable primitive (shadcn `Card`); CertStrip is a compact horizontal variant of the same data.

| Field | Type | Notes |
|---|---|---|
| `name` | text, localized | Realistic-length placeholder, e.g. "Food Safety System Certification (FSSC) 22000" — long strings expected, stress-test wrapping (Pitfall 4) |
| `issuingBody` | text, localized | e.g. "FSSC Foundation" (placeholder — no fabricated certificate/registration numbers per legal caution, Pitfall 9) |
| `logo` | Media (upload), not localized | Fixed aspect box `aspect-[3/2]`, `object-contain`, `bg-white` padding so varied-shape logos sit consistently |
| `certificatePdf` | Media (upload, PDF mimetype), not localized, optional | See PDF-link states below |
| `halal` | boolean (D-04/D-05) | Drives the elevated treatment below |

**CertCard states:**
- **Standard cert:** white `Card`, logo, Body-600 name, Label neutral-600 issuing body, PDF-download link/icon if `certificatePdf` present.
- **Halal cert (`halal: true`):** `border-2 border-accent-600`, `bg-accent-100`/`text-accent-800` "Halal Certified" badge chip (shadcn `Badge`) top-of-card, and the card spans 2 grid columns (or renders first, full-width on mobile) — satisfies D-05's "elevated placement" requirement without inventing new colors.
- **PDF present:** `<a href={pdf.url} download target="_blank" rel="noopener noreferrer" aria-label="Download {name} certificate (PDF)">` + Download icon (lucide, **no-mirror** per Phase 1's existing no-mirror list) + visible "Download PDF" label (Label token).
- **PDF absent (placeholder state):** no link rendered — instead a muted `text-neutral-600` Label-token line: "Certificate available on request" — **never render a dead/broken download link** (directly prevents the Pitfall 9 "logo without proof" trust failure while staying honest about placeholder-stage content).

**CertStrip (homepage):** same data, compact horizontal scroll-on-mobile / wrapped-row-on-desktop strip of logos only (no name/PDF), each logo linking to `/certifications#<slug>`; Halal logo gets the same `border-accent-600` treatment even in strip form.

### 6. MediaGallery

| Field | Type | Notes |
|---|---|---|
| `sectionTitle` | text, localized, optional |
| `items[]` | array (image, caption text localized, optional video-embed URL) |

Layout: responsive grid `grid-cols-2 md:grid-cols-3 gap-md`, each cell fixed `aspect-[4/3]` via shadcn `AspectRatio` + `object-cover`, lazy-loaded (`next/image` default). Caption (if present) renders as a Label-token line below the image, not overlaid (overlay text-on-photo risks contrast failures across arbitrary real photography — out of scope to solve generically). **No lightbox/modal in Phase 2** — static grid only; an expand-on-click viewer is an anti-feature-adjacent complexity for a launch-stage trust page and can be added later if analytics show demand (ponytail: skip until needed).

### 7. CTABand

| Field | Type | Notes |
|---|---|---|
| `heading` | text, localized | Heading token |
| `body` | text, localized, optional | Body token |
| `primaryCta` | group (label + href), localized label | Reuses `PrimaryButton` |
| `secondaryCta` | group (label + href), localized label, optional | Outline variant, same WhatsApp pattern as Hero's secondary CTA |

Layout: full-width band, `bg-primary-900` (dark, matches footer surface for a "closing" visual weight) with white text, centered content, `max-w-2xl mx-auto text-center`. This is the one block that breaks the white/neutral-100 alternation deliberately — it's meant to read as a distinct "action moment," reusing the footer's existing dark-surface color rather than introducing a new one.

### 8. ExportMap (D-06 — static SVG, not interactive/3D)

| Field | Type | Notes |
|---|---|---|
| `sectionTitle` | text, localized, optional |
| `highlightedCountryCodes[]` | array of ISO country codes, not localized | Drives which SVG paths render `fill-primary-500` |
| `stats[]` | array (same shape as StatsBand: value/label) | e.g. years exporting, countries served, incoterms handled |
| `svgSource` | static asset (checked into repo, e.g. a simplified world-topology SVG — not a Media upload; it's a code asset, not editor-managed content) | See a11y note below |

Layout: two variants driven by page, not a new block —
- **Homepage (compact):** map + 3-4 stat tiles side-by-side on desktop (`grid-cols-1 lg:grid-cols-2 gap-xl`, map left/inline-start, stats right/inline-end), stacked on mobile, map above stats.
- **Export Track Record page (full):** same component, larger map (`max-w-[900px] mx-auto`), stats rendered as a full StatsBand block above or below rather than side-by-side, plus a visible text list/chips of served country names below the map (see a11y note).

**A11y (map is supplementary, not the sole information channel):** the SVG wraps in `role="img"` with an `aria-label` summarizing the count (e.g., "World map highlighting 40+ countries Star Agrevolution exports to"). The actual country names are **always also rendered as visible text** (a wrapped list of country-name chips/tags below the map) — the map illustrates, it never gatekeeps information a screen-reader user can't otherwise get. Map does not mirror in RTL (see RTL Extensions above).

### 9. ContactBlock (Contact page only, D-07)

Two-column desktop layout (`grid grid-cols-1 lg:grid-cols-2 gap-2xl`), info column first (inline-start), form column second (inline-end); single column stacked on mobile, same order.

**Info column:**
- Registered address (Body token, `MapPin` lucide icon, no-mirror)
- Phone (`Phone` lucide icon, no-mirror — Phase 1's no-mirror list already covers "phone/envelope" real-world-object icons)
- Email (`Mail` lucide icon, no-mirror per Phase 1's explicit list)
- WhatsApp (`wa.me/<E164_NUMBER>?text=<url-encoded prefilled greeting>`, opens `target="_blank"`) — static link per D-07/CONTEXT (analytics wiring is Phase 4). **Icon note:** lucide has no dedicated WhatsApp brand glyph; use a single small hand-authored monochrome WhatsApp-shape SVG (one component, no new icon-library dependency) rather than a generic chat bubble, for brand recognizability — executor discretion on exact glyph source, not a new dependency. **Not icon-only:** a visible text label/value MUST sit beside the WhatsApp icon (e.g. the displayed WhatsApp number or "Message us on WhatsApp"), matching how Phone/Email/Address show their value; the icon-link also carries `aria-label="Message Star Agrevolution on WhatsApp"`.

**Form column — non-submitting inquiry stub (LEAD-01 fields, validated client-side only):**

| Field | Input | Validation |
|---|---|---|
| Name | shadcn `Input`, required | non-empty |
| Company | shadcn `Input`, required | non-empty |
| Country | shadcn `Input` (plain text, not a country-select — a full 195-country picker is RFQ-form territory per Phase 4/LEAD-02, not needed for this general-inquiry stub) | non-empty |
| Message | shadcn `Textarea`, required | min length (e.g. 20 chars) |

- Form built with `react-hook-form` + `zod` (already-approved project stack, no new dependency) purely for **client-side validation state demonstration** — no server action, no network call, per D-07.
- Each field: Label (Label token) above, `Input`/`Textarea` below, inline error text (Label token, `text-destructive` `#B91C1C`) beneath the field on validation failure, plus a `border-destructive` ring on the invalid field itself.
- **A11y (programmatic error association, required):** use shadcn's `Form`/`FormField`/`FormMessage` primitives, which wire `aria-invalid` on the input and `aria-describedby` linking it to its error message automatically. Each `Input`/`Textarea` MUST have an associated `<Label htmlFor>`. This is not optional — screen-reader users must hear the field name and its error.
- Submit button: shadcn `Button`, label **"Send Inquiry"** (see Copywriting Contract) — always enabled (never `disabled`, which reads as broken); on valid submit, the form is replaced in-place by an inline confirmation panel (`bg-primary-100`, Body token): "Thanks — inquiries aren't wired up on this preview yet. Email **sales@staragrevolution.com** or use WhatsApp above and we'll respond directly." This is the exact seam Phase 4 (LEAD) replaces with a real Server Action — same field names, same validation schema, only the submit handler changes.
- No honeypot field yet (spam defense is explicitly Phase 4/LEAD-03 scope) — leave a code comment marking the intended insertion point, do not build the field now.
