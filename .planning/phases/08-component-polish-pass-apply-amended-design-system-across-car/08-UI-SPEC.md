### §4 Button primitive consolidation

`src/components/ui/button.tsx`. **This file IS the correct customization point** — unlike `src/components/ui/card.tsx`, which Phase 6 explicitly preserved as a vendor-owned pass-through (all overrides ride call-site `cn()`), shadcn's own convention is that `ui/*.tsx` files are owned code meant to be edited for exactly this kind of brand-default consolidation. Editing `button.tsx`'s `cva()` variants here does not violate the Phase 6 card precedent — it is the same "own your components" pattern applied to the file where it belongs.

Base cva string — one token swap (removes the need for `focus-visible:ring-accent-600` at 6+ call sites, since `--ring` already resolves to `--color-accent-600`):

```diff
- "inline-flex shrink-0 items-center justify-center gap-2 rounded-md text-sm font-medium whitespace-nowrap transition-all outline-none focus-visible:border-ring focus-visible:ring-[3px] focus-visible:ring-ring/50 disabled:pointer-events-none disabled:opacity-50 aria-invalid:border-destructive aria-invalid:ring-destructive/20 dark:aria-invalid:ring-destructive/40 [&_svg]:pointer-events-none [&_svg]:shrink-0 [&_svg:not([class*='size-'])]:size-4"
+ "inline-flex shrink-0 items-center justify-center gap-2 rounded-md text-sm font-medium whitespace-nowrap transition-all outline-none focus-visible:border-ring focus-visible:ring-[3px] focus-visible:ring-accent-600 disabled:pointer-events-none disabled:opacity-50 aria-invalid:border-destructive aria-invalid:ring-destructive/20 dark:aria-invalid:ring-destructive/40 [&_svg]:pointer-events-none [&_svg]:shrink-0 [&_svg:not([class*='size-'])]:size-4"
```

`default` variant — bake in the real hover color (removes `hover:bg-primary-500` from 5 call sites):

```diff
- default: "bg-primary text-primary-foreground hover:bg-primary/90",
+ default: "bg-primary text-primary-foreground hover:bg-primary-500",
```

New `outlineOnDark` variant (removes the fragile 2x-duplicated override in `HeroBlock.tsx`/`CTABandBlock.tsx` and makes the resting-transparent background explicit instead of relying on tailwind-merge to suppress `bg-background`):

```diff
  variants: {
    variant: {
      default: "bg-primary text-primary-foreground hover:bg-primary-500",
      destructive: "...",
      outline: "...",
      secondary: "...",
      ghost: "...",
      link: "...",
+     outlineOnDark:
+       "border border-white bg-transparent text-white hover:bg-white/10",
    },
```

Call-site cleanup after the above (apply at all 8 call sites — none of these need a `className` override anymore for hover/ring/dark-outline; keep any unrelated overrides like `size="sm"`, `w-full`, etc.):

- `src/components/blocks/HeroBlock.tsx:77` — `<Button asChild>` (drop `className`)
- `src/components/blocks/HeroBlock.tsx:85-89` — `<Button asChild variant="outlineOnDark">` (drop `className`)
- `src/components/blocks/CTABandBlock.tsx:18` — `<Button asChild>` (drop `className`)
- `src/components/blocks/CTABandBlock.tsx:25-29` — `<Button asChild variant="outlineOnDark">` (drop `className`)
- `src/components/chrome/GlobalHeader.tsx:74-79` — `<Button asChild size="sm">` (drop `className`, keep `size="sm"` + responsive `hidden ... sm:inline-flex` visibility classes)
- `src/components/chrome/GlobalHeader.tsx:72` (`WhatsAppCta` override) — this is a **third, single-use** outline-on-light pattern (`border-primary-700 text-primary-700 hover:bg-primary-100`) — do NOT generalize into a variant for one call site (YAGNI); just drop the now-redundant `focus-visible:ring-accent-600` segment, keep the rest
- `src/components/chrome/MobileNavPanel.tsx:115` — `<Button asChild>` (drop `className`)
- `src/app/(site)/[locale]/products/[slug]/page.tsx:169` — `<Button asChild className="mt-lg">` (drop the hover/ring segment, keep `mt-lg`)

### §6 FAQ block (new — only if planner confirms in scope; see "FAQ Scope Note" above)

If built, follow the exact pattern of the other 12 CMS blocks:

- **Payload config:** `src/blocks/Faq.ts` — `slug: "faq"`, fields: `sectionTitle` (text, optional, matches every other block's convention), `items` (array of `{ question: text, answer: textarea }`).
- **Renderer:** `src/components/blocks/FaqBlock.tsx` — section wrapper identical to every other block: `` `${sectionBg(index)} px-md py-2xl md:px-lg md:py-3xl xl:px-xl xl:py-4xl` `` inside `mx-auto max-w-[1280px]`.
- **Primitive:** shadcn `Accordion` (`npx shadcn add accordion` — official registry, no vetting gate required). `type="single" collapsible`, first item NOT pre-opened (a defaultOpen item on a trust/compliance page reads as noise before the visitor has a question in mind — consistent with the rest of the site never forcing content open).
- **No card wrapper.** Per the `StatsBandBlock` precedent ("deliberately NO card border... reads as a lightweight band"), the accordion uses its own default `border-b` row dividers (a native accordion affordance, not the "flat spec-sheet list" anti-pattern) — do not wrap it in `rounded-card`/`shadow-card`.
- **Empty state:** zero items → the shared `t("emptyState")` generic fallback string (`blocks.emptyState`), same as every other block — never render an empty accordion shell.
- **Registration:** add to `src/blocks/index.ts`, `Pages.ts`'s `layout.blocks`, and `RenderBlocks.tsx`'s `BLOCK_MAP` under key `faq`, following `TrustBar`/`ExportProcess`/`Testimonials`'s exact Phase 7 registration pattern.
