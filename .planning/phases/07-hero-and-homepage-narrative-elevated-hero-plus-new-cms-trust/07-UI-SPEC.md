## Part 1 — Hero Elevation (`HeroBlock.tsx`, `full` variant only)

The `compact` variant (every interior page) is **byte-identical, untouched**. Only the branches below differ from current code; everything else (eyebrow, CTA buttons, `data-testid="hero"`/`data-testid="sample-count"`, WhatsApp CTA) stays exactly as-is.

| Element | Current (both variants) | New — `full` only | `compact` (unchanged) |
|---------|--------------------------|--------------------|------------------------|
| Section padding | `px-md py-3xl md:px-lg xl:px-xl` | `px-md py-3xl md:px-lg md:py-3xl xl:px-xl xl:py-4xl` (applies the Phase 6 96px rhythm step, which Phase 6 explicitly deferred to this phase) | `px-md py-3xl md:px-lg xl:px-xl` |
| Content stack gap | `gap-lg` | `gap-xl` (refined rhythm — more breathing room around the larger display headline) | `gap-lg` |
| Headline | `max-w-[42rem] text-display font-semibold text-white` | `max-w-[46rem] text-display-xl font-display font-light tracking-display text-white` | `max-w-[42rem] text-display font-semibold text-white` |
| Subhead | `max-w-[36rem] text-body text-primary-100` | `max-w-[38rem] text-body text-primary-100` (widened slightly to balance the larger headline column) | `max-w-[36rem] text-body text-primary-100` |
| Atmospheric overlay | `bg-gradient-to-t from-primary-900/80 via-primary-900/30 to-transparent` | `bg-gradient-to-t from-primary-900/75 via-primary-900/25 to-transparent` (softer stops — lets the image read through more; still a single vertical, direction-agnostic 3-stop gradient, no RTL concern) | `bg-gradient-to-t from-primary-900/80 via-primary-900/30 to-transparent` (untouched) |

**Rationale for `max-w-[46rem]`:** at 56px/300/-0.025em, the existing 42rem (672px) column wraps a typical 6-8 word headline to 3 lines; 46rem (736px) brings it back to 2 lines for the current seeded headline length ("Trusted Agricultural Exports, From Farm to Global Table") while staying well short of full-bleed, preserving the "large, thin, editorial" reading Stripe/Linear-tier heroes use.

**No new dependency, no parallax, no video** — this is a pure Tailwind-class change on an existing component. Image treatment = the softened gradient itself; do not add a separate CSS `filter` (ponytail: the gradient refinement alone satisfies "better image treatment," a filter is unrequested scope).

**Implementation shape** (for the planner — conditional on `isFull`, matching the existing `isFull` variable already in the component):

```tsx
const heroPadding = isFull
  ? "px-md py-3xl md:px-lg md:py-3xl xl:px-xl xl:py-4xl"
  : "px-md py-3xl md:px-lg xl:px-xl";
const stackGap = isFull ? "gap-xl" : "gap-lg";
const headlineClass = isFull
  ? "max-w-[46rem] text-display-xl font-display font-light tracking-display text-white"
  : "max-w-[42rem] text-display font-semibold text-white";
const subheadClass = isFull
  ? "max-w-[38rem] text-body text-primary-100"
  : "max-w-[36rem] text-body text-primary-100";
const overlayClass = isFull
  ? "bg-gradient-to-t from-primary-900/75 via-primary-900/25 to-transparent"
  : "bg-gradient-to-t from-primary-900/80 via-primary-900/30 to-transparent";
```

## Part 2 — New CMS Blocks

All three follow the exact established convention: `src/blocks/{Name}.ts` (Payload `Block` config, no field-level `localized` — cascades from `Pages.layout`), `src/components/blocks/{Name}Block.tsx` (async server component, `sectionBg(index)` for background alternation, section-rhythm classes `px-md py-2xl md:px-lg md:py-3xl xl:px-xl xl:py-4xl`), registered in `src/blocks/index.ts`, `Pages.ts`'s `blocks` array, and `RenderBlocks.tsx`'s `BLOCK_MAP`.

### 2a. TrustBar (slug: `trustBar`)

**Why not `CertStrip`:** `CertStrip` is hard-bound to the Certifications collection at render time (`getCertifications(locale)`). TrustBar is a generic, editor-authored logo/label row with no collection dependency — per CONTEXT.md, must not extend `CertStrip`.

**Field shape:**

```ts
export const TrustBar: Block = {
  slug: "trustBar",
  labels: { singular: "Trust Bar", plural: "Trust Bars" },
  fields: [
    { name: "sectionTitle", type: "text" },
    {
      name: "items",
      type: "array",
      fields: [
        // logo is OPTIONAL (unlike MediaGallery's required image) — an item
        // with no logo yet still renders as an honest text chip (see render
        // spec below), never a broken image box.
        { name: "logo", type: "upload", relationTo: "media" },
        { name: "name", type: "text", required: true },
      ],
    },
  ],
};
```

**Render treatment:** `flex flex-wrap items-center justify-center gap-x-xl gap-y-lg` row, centered (Stripe-style logo bar, distinct from `CertStrip`'s left-aligned strip). Each item:
- **Logo present:** `relative h-12 w-28 shrink-0 grayscale opacity-70` tile, `Image` with `object-contain` (static muted treatment — no hover/motion this phase).
- **Logo absent (seed state — see below):** falls back to the exact chip styling already established by `ExportMapBlock`'s country-name fallback — `rounded-full bg-neutral-100 px-md py-xs text-label text-neutral-900` (ladder: reuse the existing "missing visual asset → accessible text chip" pattern verbatim, don't invent a new one).
- **Empty array:** reuse `blocks.emptyState` i18n key (no new translation string needed).

**Seed content — Pitfall 5 constraint (no fabricated named clients):** real partner/buyer logos don't exist yet. Per this repo's existing precedent ("no lorem ipsum, no fabricated certificate/registration numbers or named clients"), seed with honest **region/segment descriptors**, not invented company names — every region below is drawn from `SERVED_COUNTRY_CODES` (real, already-seeded data), so nothing here is fabricated:

- sectionTitle: `"Trusted by Importers Across the Globe"`
- items (all logo-less → render as chips): `"Gulf & Middle East Importers"`, `"European Distributors"`, `"North American Buyers"`, `"African Trade Partners"`, `"Southeast Asian Wholesalers"`

### 2b. ExportProcess (slug: `exportProcess`)

**Field shape:**

```ts
export const ExportProcess: Block = {
  slug: "exportProcess",
  labels: { singular: "Export Process", plural: "Export Processes" },
  fields: [
    { name: "sectionTitle", type: "text" },
    {
      name: "steps",
      type: "array",
      fields: [
        { name: "title", type: "text", required: true },
        { name: "body", type: "textarea", required: true },
      ],
    },
  ],
};
```

No icon field (ladder: numbered badges are simpler than adding a second lucide allow-list and stay honest about being an ordered sequence, not a value-prop grid — don't reuse `FeatureGrid`'s icon pattern here, it would blur the two blocks' distinct roles).

**Render treatment:** semantic `<ol>` (genuinely sequential content — a real a11y/semantic win, zero cost, does not conflict with any established block convention since no prior block is a sequence). `grid grid-cols-1 gap-lg sm:grid-cols-2 md:grid-cols-5` — column count capped at 5 and reflows down for fewer steps, using the same "count → column class" lookup technique `FeatureGridBlock`'s `lgColsClass` already establishes (reuse the technique, extend the cap to 5). No connecting line/SVG between steps (ponytail: equal spacing + numbered badges communicates sequence without a direction-sensitive drawn line, which would also need `rtl:` mirroring — skip entirely, add only if a real design review flags it as insufficient).

Each `<li>`: number badge `flex size-10 items-center justify-center rounded-full bg-primary-700 text-body font-semibold text-white` showing `"01"`–`"05"` as a **literal string** (not run through `Intl.NumberFormat`) — so it never mirrors to Arabic-Indic digits regardless of locale, consistent with FOUND-03's Western-numeral requirement, by construction, with zero extra code. Title: `mt-md text-body font-semibold`. Body: `mt-xs text-label text-neutral-600`.

**Seed content** (5 steps — reuses phrasing already seeded on the `/manufacturing` and `/company` pages where the same claims exist, so nothing here is a new unverified claim):

- sectionTitle: `"How an Order Moves From Inquiry to Delivery"`
1. **Inquiry** — "Share your product, target quantity, and destination port — our export team responds within one business day."
2. **Quote** — "Receive a detailed quote covering pricing, incoterms, and lead time, scoped to your order volume."
3. **Production & QC** — "Your order enters production under documented SOPs, with quality checkpoints at intake, mid-process, and pre-dispatch."
4. **Export Documentation** — "Phytosanitary certificates, packing lists, and certificates of origin are prepared ahead of dispatch, so customs clearance stays on schedule."
5. **Delivery** — "Your shipment is tracked in transit to your port, with cold-chain and handling standards maintained until arrival."

## Typography

**Provenance note — this is not new scope.** The 6-size/3-weight scale below (14/16/28/40/52/56, weights 400/600/300) is the project's existing, already-amended type system, not a tier this phase introduces. Sequence of record:

- Phase 1's original UI-SPEC locked "exactly 4 sizes / 2 weights, 40px max."
- `06-CONTEXT.md` Locked Decision #1 explicitly amended that lock **for display tiers only**, adding both `display-lg` (52px) and `display-xl` (56px) at a new light/thin weight (300) with negative tracking. Body tiers (label/body/heading) were left untouched by that amendment and remain untouched here.
- `06-UI-SPEC.md` shipped that exact 6-size/3-weight scale (see its Typography section, lines 150-172) and its own Dimension 4 checker review **passed** it, reasoning that the count exceeds the generic 4-size/2-weight ceiling but is explicitly authorized by the CONTEXT.md display-tier amendment — the context-aware rule, not a flag/block.
- `globals.css` already ships both `--text-display-lg: 52px` and `--text-display-xl: 56px` as live tokens today (Phase 6, merged, in production — see `dc8902a`/`b2b01c9`).

**What Phase 7 actually does:** apply the already-existing `text-display-xl` token to a component (Hero `full` headline) for the first time. Display-lg and Display-xl both already exist as of Phase 6 — Phase 7 adds zero new sizes and zero new weights to the project's type system. Body tiers unchanged.

| Role | Size | Weight | Line Height | Applies to |
|------|------|--------|-------------|------------|
| Label | 14px | 400 | 1.4 | Eyebrow, stat labels, chip text (unchanged) |
| Body | 16px | 400 | 1.5 | Subhead, quote text, feature body (unchanged) |
| Heading | 28px | 600 | 1.2 | Section titles across all blocks (unchanged) |
| Display (existing) | 40px | 600 | 1.15 | Hero `compact` headline, StatsBand/ExportMap stat figures (unchanged) |
| Display LG (existing, Phase 6, not applied this phase) | 52px | 300 (light) | 1.1 | No usage this phase — carried forward for completeness only |
| **Display XL (existing token, Phase 6 — first applied this phase)** | **56px** | **300 (light)** | **1.05** | **Hero `full` headline only** — `text-display-xl font-display font-light tracking-display` |

`font-display` resolves to Geist on `en`/`fr`/`ru`, falls back to Plex on `ar` (Phase 6 wiring, unchanged). `font-light` stays reserved for the two existing display tiers — no other element in this phase uses it.
