This is mandatory, not optional: Radix's default `Presence` unmounts closed content, and an element being removed from the DOM never gets to play a closing transition — the accordion would animate open and snap shut, which looks identical to the bug you are fixing (RESEARCH Pitfall 4).

New className on `AccordionPrimitive.Content`: `grid grid-rows-[0fr] text-sm transition-[grid-template-rows,visibility] duration-300 ease-[cubic-bezier(0.16,1,0.3,1)] data-[state=closed]:invisible data-[state=open]:grid-rows-[1fr] motion-reduce:transition-none`. Change the inner `<div>`'s classes to `cn("overflow-hidden pt-0 pb-4", className)` — `overflow-hidden` moves from the outer element to the inner one, because the inner div is what must clip while the outer grid row collapses from `0fr` to zero height.

Two details worth understanding rather than copying blindly:

`grid-template-rows` is the one carve-out from D-03's transform/opacity-only rule, granted explicitly in CONTEXT.md's accordion guidance. It is chosen over the alternative (keyframes reading Radix's `--radix-accordion-content-height`) because it needs no JS height measurement, triggers no layout thrash from animating `height`, and does not couple this file to a Radix-internal CSS custom property surviving future upgrades. Note that `tw-animate-css` — installed in plan 09-01 — ships its own accordion utility classes whose keyframes animate `height` directly; those are exactly the thing D-03 forbids and are deliberately not used here (RESEARCH Pitfall 1).

`data-[state=closed]:invisible` plus `visibility` in the transition list is the accessibility half of the fix, and it is not optional. `forceMount` keeps collapsed answers in the DOM, and Radix drops its own `hidden` attribute when content is force-mounted — so without a guard, every collapsed FAQ answer stays in the accessibility tree and the tab order while its trigger reports `aria-expanded="false"`. `visibility: hidden` removes it from both. Listing `visibility` in the transition property list is what makes this behave correctly rather than cutting the animation short: `visibility` interpolates as a step function, so opening reveals immediately while closing stays visible for the full 300ms and only then hides.

Then update the second FaqBlock test in `tests/int/blocks-placeholder.spec.ts`.
