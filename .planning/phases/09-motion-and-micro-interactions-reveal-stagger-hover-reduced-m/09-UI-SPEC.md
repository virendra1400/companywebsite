## Motion Contract

> The substantive design contract for this phase. All values are LOCKED from `09-CONTEXT.md` decisions and validated by `09-RESEARCH.md`'s architecture. Executor implements these verbatim; deviations require a plan-time justification.

### 1. Motion register (hard constraint)

- **Tier:** Restrained "fluid CSS" — Stripe/Linear trust-first register. No scroll-hijacking, no pinned/sticky-stack sections, no magnetic-cursor physics, no spring/gesture choreography.
- **Animatable properties:** `transform` and `opacity` ONLY. `grid-template-rows` is the single named exception (accordion only, §6). Never animate `top`/`left`/`width`/`height`/`max-height` directly.
- **Trigger mechanism:** `IntersectionObserver` only. `window.addEventListener('scroll')` is banned anywhere in this phase's code.
- **No new animation-orchestration dependency.** CSS/Tailwind + one ~30-line custom `useInView` hook. `tw-animate-css` is a CSS-utility package (not an animation library) added solely to unblock pre-existing broken shadcn Sheet/DropdownMenu/Select classes.

### 2. Section-level reveal (`Reveal` component)

| Property | Value |
|----------|-------|
| Shape | Fade + upward rise |
| Initial state | `opacity: 0`, `translateY(24px)` (use Tailwind `translate-y-6`) |
| Revealed state | `opacity: 1`, `translateY(0)` |
| Duration | 0.6s |
| Easing | `cubic-bezier(0.16, 1, 0.3, 1)` (ease-out-expo) |
| Trigger | IntersectionObserver, threshold `0.2`, fires once then `unobserve()` — never replays on scroll-up-then-down |
| Scope | Every non-hero block rendered by `RenderBlocks.tsx` (uniform, D-07) |
| Hero exception | `HeroBlock` is NEVER wrapped in `Reveal` — must paint immediately for LCP. `RenderBlocks.tsx` special-cases `blockType === "hero"` explicitly, not via threshold timing |
| Reduced motion | `useInView` checks `matchMedia('(prefers-reduced-motion: reduce)')` on mount; if reduced, sets `inView=true` immediately, skips attaching the observer entirely — content renders fully visible, no transition class ever applies |

### 3. Item-level stagger (`RevealItem` component)

| Property | Value |
|----------|-------|
| Base shape | Same fade+rise as `Reveal`, own `IntersectionObserver` instance per item |
| Initial transform (default `direction="up"`) | `translate-y-4` |
| Directional variants (D-10, use sparingly) | `direction="start"`: `-translate-x-4 rtl:translate-x-4`; `direction="end"`: `translate-x-4 rtl:-translate-x-4` — logical direction via Tailwind `rtl:` variant, never hardcoded physical direction |
| Duration | 0.5s |
| Easing | `cubic-bezier(0.16, 1, 0.3, 1)` |
| Stagger increment | `STAGGER_MS = 50` — applied as `transitionDelay: ${min(index, STAGGER_CAP) * 50}ms` |
| Stagger cap | `STAGGER_CAP = 8` items — delay plateaus after item 8 regardless of grid size (prevents a slow item-by-item march on large catalogs, protects CAT-03 scalability) |
| Scope | `.map()` loops inside grid-shaped blocks: FeatureGrid, Testimonials, MediaGallery, TrustBar, CertStrip, plus `ProductCard`/`InsightCard` catalog grids |
| Reduced motion | Same `motion-reduce:` fallback as §2 — instant full visibility, no stagger delay perceptible |

### 4. Hover treatment (cards)

| Property | Value |
|----------|-------|
| Lift | `translateY(-2px)` to `translateY(-4px)` (planner's call within this range per component) |
| Shadow | `shadow-card` → `shadow-card-hover` (existing Phase 6 tokens, no new values) |
| Duration | ~150ms, existing `ProductCard.tsx` pattern (`transition-transform duration-150`) — reuse as the model, don't reinvent |
| Image cards only (ProductCard, InsightCard) | Optional additional `scale(1.03–1.05)` on the image element if it reads premium, not gimmicky — planner's discretion per component |
| Trigger | Pure CSS `:hover`/`group-hover:` — no JS, no observer |

### 5. Tap / active feedback (buttons)

| Property | Value |
|----------|-------|
| Treatment | `active:scale-[0.98]` |
| Edit site | ONE location: `buttonVariants` base `cva` string in `src/components/ui/button.tsx` (Phase 8 P02 precedent — token-level edits to the base cva string are in-scope; not per-call-site) |
| Directionality | Transform-only (`scale`), identical LTR/RTL — no logical-property concern |
| Reduced motion | `motion-reduce:active:scale-100` — the scale change is suppressed entirely under reduced motion (this is the one case where CONTEXT.md's "instant but present" rule simplifies to "no visual delta," since a 2% scale nudge has no non-animated equivalent worth keeping) |

### 6. Reduced-motion contract (`prefers-reduced-motion: reduce`)

| Motion type | Reduced-motion behavior |
|-------------|--------------------------|
| Scroll-reveal (Reveal/RevealItem) | Fully disabled — content renders immediately visible, no transition, no observer attached (checked once via `matchMedia` on mount) |
| Hover state change (`shadow-card-hover`, lift) | State STILL CHANGES, but instantly — `motion-reduce:transition-none` removes the animation, not the state |
| Active/tap (`scale-[0.98]`) | Suppressed via `motion-reduce:active:scale-100` (see §5) |
| Accordion open/close | `motion-reduce:transition-none` on the `grid-template-rows` transition — content still opens/closes, just without animation |
| WhatsApp floating button entrance | `motion-reduce:animate-none` — button renders in final state immediately |

This is the standard WCAG-aligned interpretation (kill autoplaying/non-user-initiated motion; keep state changes, drop their animation) — not a blanket "kill all motion."

### 7. Accordion fix (D-13, `src/components/ui/accordion.tsx`)

| Property | Value |
|----------|-------|
| Problem | `animate-accordion-up`/`-down` classes reference no matching keyframes anywhere — FAQ accordion currently has zero open/close animation |
| Fix | `grid-template-rows: 0fr` (closed) → `1fr` (open) via `data-[state=open]:grid-rows-[1fr]`, `transition-[grid-template-rows] duration-300 ease-[cubic-bezier(0.16,1,0.3,1)]` |
| Required prop | `forceMount` on `AccordionPrimitive.Content` — without it, Radix's default `Presence` unmounts the content on close and the transition never plays (closes instantly, "looks broken" identically to the pre-fix state) |
| Explicitly NOT used | `tw-animate-css`'s stock `animate-accordion-up`/`-down` classes — those animate `height` directly, violating the transform/opacity-only constraint (§1) |
| Reduced motion | `motion-reduce:transition-none` |
| RTL | `grid-template-rows` has no directionality — works identically LTR/RTL, no `rtl:` variant needed |

### 8. Floating WhatsApp button + persistent CTAs (D-09)

| Property | Value |
|----------|-------|
| Entrance | `@theme` keyframe `--animate-float-in`: `opacity 0→1`, `translateY(16px)→0`, `scale(0.9)→1`, 0.5s, `cubic-bezier(0.16, 1, 0.3, 1)`, plays once on paint |
| Mechanism | Pure CSS `animate-*` utility class on the existing Server Component (`WhatsAppFloatingButton.tsx` stays RSC — no client boundary needed, always in viewport at mount, no IntersectionObserver trigger required) |
| Hover | Existing `hover:bg-primary-500` color transition — unchanged, add nothing new beyond what's already there unless found abrupt |
| Reduced motion | `motion-reduce:animate-none` |

### 9. Chrome polish (D-08 — light touch only)

- GlobalHeader/GlobalFooter/nav: NOT a redesign. Only tighten currently-abrupt transitions (e.g. mobile menu open/close).
- `MobileNavPanel.tsx` is already `"use client"` with Radix Sheet/Dialog `data-state` wiring in place — this phase only needs `tw-animate-css`'s `fade-in-0`/`slide-in-from-{side}` utility classes to resolve (no new JS, no new component logic).

### 10. Component boundary rules (non-visual but load-bearing for the contract)

- Existing block components (`FeatureGridBlock.tsx`, `StatsBandBlock.tsx`, etc.) MUST remain Server Components (`async`, unchanged data-fetching). Only new leaf components (`Reveal`, `RevealItem`, `useInView`) get `"use client"`.
- New motion code lives in `src/components/motion/` (NOT `src/hooks/` — that directory is reserved for Payload CMS lifecycle hooks; naming collision risk flagged in RESEARCH.md Pitfall 3).
- `RenderBlocks.tsx` wraps already-rendered RSC `children` in `<Reveal>` — it does not change what data each block fetches.

## UI Considerations

Applicable state considerations resolved: 4 covered, 0 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| Reduced-motion state | All reveal/hover/active/accordion/entrance motion sitewide | ✅ covered | `prefers-reduced-motion: reduce` fully disables scroll-reveal (content renders visible immediately, no observer attached); hover/active/accordion state changes remain but lose their transition duration via `motion-reduce:transition-none` / `motion-reduce:active:scale-100` / `motion-reduce:animate-none` — see Motion Contract §6 |
| RTL / directional mirroring | Directional-slide `RevealItem` cards (D-10) | ✅ covered | `direction="start"`/`"end"` variants pair `-translate-x-4` with `rtl:translate-x-4` (and inverse) — Tailwind's `rtl:` variant flips sign for Arabic; `npm run lint:rtl` must stay green (does not catch this specific semantic case per RESEARCH.md Pitfall 6, so a manual/e2e Arabic-locale visual check is also required at verification time) |
| Overflow / large-collection (many items) | Product/Insights catalog grids, any grid-shaped CMS block | ✅ covered | `STAGGER_CAP = 8` plateaus per-item delay after the 8th item regardless of grid size — prevents a multi-second item-by-item reveal march on large catalogs (protects CAT-03 scalability intent) |
| Zero-replay / stateful reveal | Every scroll-revealed section/item, sitewide | ✅ covered | `IntersectionObserver.unobserve()` fires immediately after first intersect — scrolling a section out of view and back in never re-triggers the reveal (D-06) |

No empty/loading/error UI states are introduced or altered by this phase — it is a motion-only pass over already-existing, already-populated UI. Empty/loading/error copy and layout remain exactly as locked in prior phases.
