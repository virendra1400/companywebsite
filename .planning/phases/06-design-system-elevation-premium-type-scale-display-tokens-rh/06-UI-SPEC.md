# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase boundary (source: 06-CONTEXT.md):** This is a **design-TOKEN phase, not a page-building phase.** It amends `src/app/globals.css` `@theme` tokens only — new display-tier typography, a locale-scoped Latin display face, bumped section rhythm, and a tightened card/hairline/shadow system. **No pages are built, no colors change, no body-text tokens change, no Hero component rebuild** (that's Phase 7). Where this spec gives an exact px/em value inside a CONTEXT.md-given range, the value is this agent's documented discretion call — not a re-opening of the locked range.

## Token Amendment — `globals.css` `@theme` (the actual deliverable)

Current state (read from `src/app/globals.css` before this phase): spacing scale `xs`(4)…`3xl`(64), typography `label`(14)/`body`(16)/`heading`(28)/`display`(40) at exactly 2 weights (400/600), no radius/shadow tokens (components rely on Tailwind's static `rounded-lg`/`rounded-xl`/`shadow-sm`/`shadow-md`), section padding recipe `px-md py-2xl md:px-lg md:py-3xl xl:px-xl` (48px→64px, flat past `md`) used identically across 9 block components.

Append to the existing `@theme` block (do not touch the color ramp, `--spacing-xs..3xl`, or any `--text-label/body/heading/display*` key — those stay byte-identical):

```css
/* ---- Phase 6 amendment: display-tier type scale, rhythm, cards ---- */

/* Display tiers — ADDED above the existing --text-display (40px/600,
   UNCHANGED, still used by StatsBand/ExportMap stat figures and the
   compact interior-page hero). Two new tiers for premium hero use
   (Phase 7 wires these into HeroBlock's headline — not applied here). */
--text-display-lg: 52px;
--text-display-lg--line-height: 1.1;
--text-display-lg--font-weight: 300;
--text-display-xl: 56px;
--text-display-xl--line-height: 1.05;
--text-display-xl--font-weight: 300;

/* Negative tracking — ONE proportional (em-based) token shared by both new
   tiers so it self-scales: -0.025em == -1.3px@52px / -1.4px@56px, matching
   the Stripe 56px/-1.4px reference point exactly at the xl tier. */
--tracking-display: -0.025em;

/* font-light (300) is Tailwind's own default-theme weight utility — it was
   never removed by this file (no `--font-weight-*: initial` reset exists),
   so no new font-weight token is needed. Contract: font-light is RESERVED
   for text-display-lg/text-display-xl only — body/heading/label keep using
   only font-regular (400, custom key) / font-semibold (600). */

/* Locale-scoped Latin display face. Mirrors the existing --font-sans
   nested-fallback pattern (see comment above --font-sans in this file):
   when the locale layout is `ar`, --font-geist-display is never set on
   <html>, so this falls back to --font-sans (Plex / Plex Arabic) —
   Arabic NEVER receives the Latin display face. */
--font-display: var(--font-geist-display, var(--font-sans));

/* Section rhythm — NEW 4th step bumping the xl breakpoint from 64px to
   96px. Mobile (48px) and tablet (64px) steps are unchanged; the range
   64-96px is now covered across the responsive scale, not just at one
   breakpoint. */
--spacing-4xl: 96px;

/* Card system — tightened, single source of truth replacing the current
   rounded-lg/rounded-xl split, and replacing default shadow-sm/shadow-md
   with a subtle brand-tinted (primary-900) ambient shadow instead of a
   neutral drop-shadow stack. Border color is UNCHANGED (neutral-300). */
--radius-card: 10px;
--shadow-card: 0 1px 2px 0 rgb(15 46 34 / 0.04), 0 1px 1px 0 rgb(15 46 34 / 0.03);
--shadow-card-hover: 0 8px 20px -4px rgb(15 46 34 / 0.10), 0 2px 6px -2px rgb(15 46 34 / 0.05);
```

These key names follow Tailwind v4's theme namespace convention already used in this file (`--text-*`, `--spacing-*`), so utilities auto-generate with zero extra CSS: `text-display-lg`, `text-display-xl`, `tracking-display`, `font-display`, `p-4xl`/`py-4xl`/`px-4xl`, `rounded-card`, `shadow-card`, `shadow-card-hover`. `font-light` already exists (Tailwind default, unremoved).

### Font loading wiring (`src/app/(site)/[locale]/layout.tsx`)

Add a Geist loader beside the existing Plex loaders, and gate its `variable` class the same way `fontVar` is already gated on `locale === "ar"`:

```ts
const geistDisplay = Geist({
  subsets: ["latin"],
  weight: ["300"],
  variable: "--font-geist-display",
  display: "swap",
});
```

```ts
const fontVar = locale === "ar" ? plexSansArabic.variable : plexSans.variable;
const displayVar = locale === "ar" ? "" : geistDisplay.variable; // NEW — never on ar
```

`<html lang={locale} dir={dir} className={\`${fontVar} ${displayVar}\`}>` — trims to a single class when `displayVar` is empty (ar). This is the entire "locale-scoped Latin display font wiring" deliverable; no other file changes.

### Tabular figures — no new token needed

Tailwind v4 ships `tabular-nums` as a built-in `font-variant-numeric` utility already (framework-native, ladder rung 3/4 — reuse, don't reinvent). CONTEXT.md explicitly allows "the equivalent Tailwind utility" — this is it. Contract: numeric/stat cells (StatsBand values, future SpecTable rows) use the class `tabular-nums`. **Wiring it into StatsBandBlock/SpecTable is Phase 8 scope per CONTEXT — this phase only needs the utility to exist, which it already does.**

### Section rhythm recipe (contract for block components — applying it is this phase's scope per the roadmap goal)

Replace the current recipe used identically in `CTABandBlock`, `ContactBlockView`, `CertStripBlock`, `DocumentCardBlock`, `FeatureGridBlock`, `MediaGalleryBlock`, `ExportMapBlock`, `RichTextBlock`, `StatsBandBlock`:

- Old: `px-md py-2xl md:px-lg md:py-3xl xl:px-xl`
- New: `px-md py-2xl md:px-lg md:py-3xl xl:px-xl xl:py-4xl`

`HeroBlock` is explicitly **excluded** from this recipe change (its padding/sizing is Phase 7 "Hero & Homepage Narrative" scope — do not touch here).

### Card recipe (contract for card-family components)

`ProductCard`, `InsightCard`, `CertCard` (via shadcn `Card`) currently mix `rounded-lg` and the `Card` primitive's default `rounded-xl`, with `shadow-md` only on hover. Converge on:

- `rounded-card` (10px) replacing `rounded-lg`/relying-on-default-`rounded-xl`
- `shadow-card` as the resting state (replacing implicit `shadow-sm` from the `Card` primitive)
- `shadow-card-hover` replacing `group-hover:shadow-md` / `group-focus-visible:shadow-md`

Override happens at the call site via the existing `cn()` (`tailwind-merge`) pattern already used by `ProductCard`/`InsightCard` to override the `Card` primitive's defaults — same mechanism, new values. **Do not hand-edit `src/components/ui/card.tsx`** (vendor-owned, per the existing RTL-lint exemption comment).

## UI Considerations

Applicable state considerations resolved: 2 covered, 1 backstop, 1 unresolved (deferred by design).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| Font-loading fallback | `text-display-lg` / `text-display-xl` (Geist, `font-display`) | ✅ covered | `display: "swap"` set on the Geist loader; `--font-display: var(--font-geist-display, var(--font-sans))` falls back to Plex if the font hasn't loaded yet or fails to load — no invisible text (FOIT), never a blank/broken heading. |
| RTL/locale leak | `ar` locale display headings | ✅ covered | `layout.tsx` only appends `geistDisplay.variable` when `locale !== "ar"`; on `ar`, `--font-geist-display` stays unset at `<html>` scope, so `--font-display` resolves to `--font-sans` (Plex Sans Arabic) automatically — Latin display face never reaches Arabic content. |
| Visual regression (token-level) | Homepage + one trust page (CONTEXT.md non-negotiable check) | 🧪 backstop | No automated visual-regression test exists in this repo; the CONTEXT.md-mandated check ("verify no layout regression on at least the homepage and one trust page") is a manual verification step at execute-time, not a shipped assertion — if skipped, this is `insufficient_spec` at verify time, not a silent pass. |
| Long-headline overflow at new display sizes | `text-display-xl` applied to a real headline | ⚠ unresolved | Explicitly out of scope this phase (CONTEXT.md: "Applying the new display tokens to the actual Hero component → Phase 7"). The token itself has no `max-width`/wrap constraint baked in — Phase 7 owns pairing it with a `max-w-*` container and verifying wrap behavior on long CMS-authored headlines. |

## RTL & Locale Contract (extends Phase 1's, this phase's specific additions only)

| Concern | Rule |
|---------|------|
| Latin display font scope | `font-display` (Geist) applies **only** when the locale layout sets `--font-geist-display` — i.e. `en`/`fr`/`ru`. Never applied to `ar` locale content, never applied to body text in any locale. |
| Logical properties | All new utilities (`p-4xl`/`py-4xl`/`px-4xl`, `rounded-card`, `shadow-card`) are direction-agnostic (padding/radius/shadow have no left/right physical variant used here) — no `rtl:` override needed for any token in this phase. |
| `lint:rtl` | Must stay green after this phase. `scripts/check-physical-direction.mjs` bans `rounded-l`/`rounded-r`/`border-l`/`border-r` (word-boundary matched) — `rounded-card` and `shadow-card`/`shadow-card-hover` do not match any banned pattern; verified by inspection of the regex list. |
| Numerals / tabular figures | `tabular-nums` is direction-agnostic and numeral-system-agnostic — does not affect the existing `numberingSystem: "latn"` requirement for Arabic number formatting (unrelated concern, both stay in force independently). |
