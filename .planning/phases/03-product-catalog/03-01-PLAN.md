<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL slug → Payload query | `getProduct(slug)` passes the URL segment into a `where: { slug: { equals } }` query |
| Editor (/admin) → collection write | Authenticated staff create/edit Products/Categories |
| Public visitor → published content | Anonymous reads must never surface `published:false` products |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | getProduct / getProductsByCategory | mitigate | Both helpers hard-filter `where: { published: { equals: true } }`; the seed's `Draft Sesame Seeds` fixture + the int published-exclusion assertion prove drafts never reach the public list |
| T-03-02 | Tampering / Injection | getProduct slug param | accept | Slug is used only inside Payload's parameterized `where equals` (ORM, no raw SQL interpolation); `slug` is unique+index at schema level — same audited boundary as Pages.slug (ASVS V5) |
| T-03-03 | Elevation of Privilege | Categories/Products access control | mitigate | Both collections use the established `Boolean(user)` access shape; public reads go through Local API `overrideAccess:true` exactly as every existing collection — no new bypass (ASVS V4) |
| T-03-04 | Tampering | product image uploads | accept | imageGallery relates to the existing `Media` collection, which already restricts `mimeTypes: ["image/*","application/pdf"]` — no collection-specific upload surface introduced |
</threat_model>
