# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This EXTENDS the locked Phase 1 (`01-UI-SPEC.md`) and Phase 2 (`02-UI-SPEC.md`) design systems.** Tokens, fonts, colors, spacing scale, type scale, RTL contract, and the block/card conventions are **not re-derived** — every value below is a direct reuse or an explicitly-flagged extension. This document adds the **Product Catalog** page/component contract only: CatalogIndex, ProductCard, ProductDetail, SpecTable. Phase 1 chrome (GlobalHeader/GlobalFooter/LanguageSwitcher/MobileNavPanel/LocaleFallbackNotice) wraps every catalog page unchanged; Phase 2's CertCard and MediaGallery patterns are reused, not rebuilt.

**Accent reserved-for list — Phase 3 additions (extends, does not replace, Phase 1/2's list):**
- Category anchor-nav active-chip indicator (matches Phase 1's language-switcher active-locale precedent — underline/fill on the currently-scrolled-to category chip)
- Halal cert badge on ProductDetail's applicable-certifications row — **pre-existing Phase 2 use, reused verbatim, not a new accent consumer**

**Category tag on ProductCard is NOT accent-colored** — it uses `bg-neutral-100 text-neutral-900` (a plain shadcn `Badge` `variant="secondary"`), consistent with "accent reserved for trim/badges/dividers where it signals brand-level trust (certs, active nav), never a generic metadata tag." A category tag is wayfinding metadata, not a trust signal — using gold there would dilute the reserved-for discipline.

**Non-halal applicable-certification badges on ProductDetail** reuse Phase 2's CertCard **standard** (non-halal) treatment: plain `neutral-300` border, no accent. Only halal gets the accent border/badge, exactly as Phase 2 established.

## RTL & Locale Contract — Phase 3 Extensions

Everything in Phase 1/2's RTL contract applies unchanged (logical properties only, `dir` server-set, Western numerals for `ar`, `<bdi>` for mixed BiDi content, CSS Grid auto-flow needs no extra rules). Additions specific to catalog content:

| Concern | Rule |
|---|---|
| **Product image gallery does not mirror** | Per Phase 2's "geographic maps do not mirror" precedent: product photography carries no inherent reading-direction — the gallery grid/thumbnail order stays in **source/CMS array order** in both `ltr` and `rtl` (do NOT flex-reverse the gallery in RTL). Only surrounding text/labels use logical properties. |
| **SpecTable is RTL-safe via logical properties, not column-swap** | Label/value pairs render as a two-column CSS Grid (`grid-cols-[auto_1fr]` or `grid-cols-2`) using `text-start`/`text-end` — never `text-left`/`text-right`. In RTL, the grid auto-flows so the label column sits at the visual **inline-start** (right in RTL) automatically via `dir` — no manual column reordering needed. |
| **Numeric/unit specs in mixed content** | Any spec value combining a Latin unit with Arabic text (e.g., "25 كجم" for "25 kg") wraps the Latin/numeral run in `<bdi>`, per the Phase 1 mixed-BiDi pattern — applies to packaging weight/size specs. |
| **Category anchor-nav** | Chip row uses logical `gap-sm` + `flex-wrap`; scroll-to-anchor behavior (if implemented) uses `scrollIntoView` (direction-agnostic, no manual offset math needed). |
| **Product/category slugs in URLs** | Slugs stay Latin/ASCII regardless of locale (standard CMS-slug practice) — no RTL concern; only the visible product **name** localizes, not the URL segment. |

## Component Inventory

### 1. ProductCard (CatalogIndex grid item)

Reuses the shadcn `Card` primitive — same base component family as Phase 2's `CertCard` and `FeatureGrid` tiles, for visual consistency across the site's card language.

| Field rendered | Source | Notes |
|---|---|---|
| Image | `imageGallery[0]` (first gallery image) | `AspectRatio` `ratio={4/3}` (matches Phase 2 MediaGallery's aspect convention), `object-cover`, `next/image` with `sizes="(min-width: 1024px) 25vw, (min-width: 768px) 33vw, 50vw"` |
| Name | `name` (localized) | Body-600 (16/600/1.5), `line-clamp-2` guard for long names |
| Teaser | `shortDescription` (localized) | Body (16/400/1.5), `line-clamp-2` — truncation is CSS-native (Pitfall 4: placeholder teasers must be realistic-length prose, not one-word stubs, so the clamp is exercised in dev) |
| Category tag | `category.name` (relationship, localized) | shadcn `Badge variant="secondary"` (`bg-neutral-100 text-neutral-900`, Label token), positioned top-inline-start overlaying the image OR directly below the image — **planner's discretion**; if overlaid, require a `bg-white/90` chip backing to guard contrast against arbitrary photography (same contrast-risk logic Phase 2 used to reject text-over-photo captions) |

**Layout:** entire card is a single `<a href="/products/[slug]">` (or wraps a Next `Link`) — the whole card is the tap target, not just the name, for a larger/more forgiving mobile hit area. `Card` padding `p-md` mobile / `p-lg` desktop (matches Phase 2's FeatureGrid tile padding convention). Hover/focus: subtle `-translate-y-[1px]` (per taste-technique "tactile feedback", composited transform only) + `shadow` bump; focus-visible ring uses `accent-600` (gold), consistent with Phase 1's PrimaryButton focus-ring precedent.

**Placeholder image absent state:** if `imageGallery` is empty, render a `bg-neutral-100` placeholder box with a centered lucide `ImageOff` icon (`text-neutral-600`) — never a broken `<img>` or blank white box (same "never render a dead asset silently" discipline as Phase 2's CertCard PDF-absent state).

### 2. CatalogIndex (page: `/products`)

Composition, rendered inside existing Phase 1 chrome:

```
Hero (compact variant, "Our Products" / localized eyebrow optional)
→ [optional] Category anchor-nav (sticky chip row, see below)
→ per Category (sorted by displayOrder), in an alternating-background section:
    - Category section header: Heading token (`<h2>`), optional category short description (Body, `max-w-[720px]`)
    - Product grid: `grid-cols-2 md:grid-cols-3 lg:grid-cols-4 gap-md md:gap-lg`
→ CTABand (reused from Phase 2, "Request a Quote" / "Chat on WhatsApp")
```

- **Category anchor-nav** (Claude's discretion, RECOMMENDED given D-05's "optional"): a horizontally-scrollable (mobile) / wrapped (desktop) row of `Badge`/outline-`Button` chips just below the Hero, one per category, `href="#<category-slug>"`. Each category section header carries a matching `id="<category-slug>"` anchor target. Sticky (`sticky top-[72px]` desktop-header-height, or non-sticky — planner's call at build time) is optional polish, not required for CAT-01.
- **Empty category (zero published products):** section still renders its header, followed by the Phase 2 generic empty-state copy pattern ("This section is being updated — check back shortly.") rather than an empty grid — reuses the existing empty-state copywriting convention, no new copy invented.
- **Zero categories/zero products at all (pre-seed state):** whole-page empty state — Heading "Our catalog is being prepared." / Body "Check back shortly, or [contact us directly](/contact) about specific products." (new copy, same shape as Phase 2's Certifications empty state — see Copywriting Contract below).

### 3. ProductDetail (page: `/products/[slug]`)

Composition:

```
Hero (compact variant) OR a lighter in-page header — see note below
→ Two-column region (desktop) / stacked (mobile):
    - Gallery column (inline-start)
    - Info column (inline-end): name (h1, Display), shortDescription/description, RFQ CTA
→ SpecTable region (full-width, below the two-column region)
→ Packaging region (full-width or folded into SpecTable — planner's call, see SpecTable below)
→ Applicable Certifications region (CertCard reuse, horizontal strip or small grid)
→ CTABand (reused, general "Request a Quote"/"Chat on WhatsApp" — NOT the per-product RFQ CTA, which is the dedicated CTA above)
```

**Hero decision (Claude's discretion, resolved here):** do **NOT** use the full/compact photographic Hero for product detail pages — a second full-bleed photo hero competing with the gallery immediately below it violates the "one focal point per page" rule inherited from Phase 1/2. Instead: a lightweight **PageHeader** region — breadcrumb (`Products / [Category] / [Product name]`, Label token, chevron separator that DOES mirror in RTL per Phase 1's iconography table) + product name as `<h1>` (Display token) + category tag (Badge, same treatment as ProductCard's). Background `bg-white`, `py-lg md:py-xl` (lighter than a full Hero's `py-3xl`) — the **gallery is the visual anchor** of this page, not a photographic hero.

**Two-column region:**
- Desktop: `grid grid-cols-1 lg:grid-cols-2 gap-2xl` — gallery inline-start, info inline-end (mirrors Phase 2's ContactBlock column-order pattern, auto-reverses via `dir`).
- Mobile: single column, gallery first, then info — same DOM order as desktop (no reordering trick needed).

**Gallery (reuse Phase 2 MediaGallery conventions, adapted — no new component, no lightbox per the existing anti-feature ruling):**
- Primary image: `AspectRatio ratio={4/3}` (or `1/1` if product photography is more square-cropped — planner's call, pick ONE ratio and use it consistently across all products), `object-cover`, `next/image priority` (LCP candidate on this page).
- Remaining gallery images: a static thumbnail row below the primary image, `grid grid-cols-4 gap-sm` (or a horizontally-scrollable row on mobile if more than 4 images — `overflow-x-auto` with `scroll-snap-type: x mandatory`, no JS carousel library). Clicking/tapping a thumbnail swaps the primary image (simple client-state swap, no modal/lightbox — consistent with Phase 2's explicit "no lightbox" ruling).
- Thumbnail active state: `ring-2 ring-primary-700` on the selected thumbnail (reuses primary brand color, not accent — this is a functional selection state, not a trust badge).
- **A11y (required, not optional):** each thumbnail is a real `<button type="button">` (not a bare clickable `<img>`/div) with an accessible name `aria-label="View image {n} of {total}"` (next-intl chrome string), and the selected thumbnail carries `aria-pressed="true"` (or `aria-current="true"`) so the state is exposed to screen readers, not just the visual ring. Keyboard-focusable with a visible focus ring.
- Empty gallery: same `ImageOff` placeholder pattern as ProductCard.

**Info column:**
- `shortDescription` renders as a lead paragraph, Body token, `font-semibold` (Body-600) — one level of visual emphasis above the full `description`.
- `description` (rich text) renders via the existing Phase 2 RichText container convention: `max-w-[720px]`, Body token paragraphs.
- **RFQ CTA** (D-03): `PrimaryButton` (reused, `primary-700` fill, unchanged from Phase 1), label "Request a Quote for This Product" (see Copywriting Contract), `href="/contact?product=<slug>&productName=<url-encoded name>"` — query-param context only, no functional form wiring this phase (Phase 4/LEAD-02 seam). Positioned directly below `shortDescription`, above the fold on desktop.

**SpecTable component (D-04 — the core new primitive this phase):**

| Aspect | Spec |
|---|---|
| Data | `specifications[]` — repeatable `{ label, value }`, both localized |
| Layout | CSS Grid, two columns: `grid grid-cols-[minmax(120px,auto)_1fr] md:grid-cols-[minmax(160px,auto)_1fr]` — label column auto-sized to content (capped), value column fills remaining width. **Grid, not flex-`calc()`** per taste-technique guidance. |
| Semantics (required a11y) | Render as a description list — `<dl>` wrapper, each row `<dt>` (label) + `<dd>` (value) — so screen readers associate each value with its label. Use CSS Grid (`display: grid` on the `<dl>`, `grid-template-columns: [track]`) for the visual 2-col layout; do NOT use bare `<div>`s with no label/value association. `dt`/`dd` styling per the Typography rows above. |
| Row rhythm | Each row `py-sm` with a `border-b border-neutral-300` divider (last row: no border) — NOT a boxed/bordered table-cell grid (taste-technique: "spec tables — 2-col grid or grouped chunks, not row-by-row heavy borders"); this is a single hairline divider per row, restrained, matches the site's "thin divider" accent-adjacent aesthetic already used for nav/footer dividers |
| Label style | Label token (14/400/1.4), `text-neutral-600`, `text-start` |
| Value style | Body-600 (16/600/1.5), `text-neutral-900`, `text-start` |
| Zebra/section background | Whole SpecTable sits on `bg-neutral-100` card (`Card`-wrapped, `p-lg`, matches CertCard's card-surface convention) — no per-row zebra striping (would conflict with the single-hairline-divider restraint above) |
| Long value wrapping | Values wrap normally (`break-words`); no `nowrap`/truncation on spec values — specs must be fully readable, unlike the ProductCard teaser's intentional clamp |
| Empty specifications | If `specifications` is empty, the SpecTable region doesn't render at all (no empty-table shell) — omit the region rather than show a header with zero rows |
| RTL | Grid auto-flows label-then-value at inline-start→inline-end in both directions via `text-start`, no manual swap (see RTL Extensions above) |
| Packaging | Rendered as **one additional row inside the same SpecTable** (label: "Packaging" / localized value from the `packaging` field) rather than a separate component — D-02 lists packaging as a sibling field to specifications, and visually it reads identically to a spec row; avoids inventing a second table for one field. If `packaging` is empty, that single row is simply omitted (same per-row omission logic, not a whole-region omission). |

**Applicable Certifications region (reuse Phase 2 CertCard, no new component):**
- `certifications[]` relationship → render each as the existing `CertCard` component (imported as-is from `src/components/blocks/CertCard.tsx`), in a `grid grid-cols-2 md:grid-cols-3 gap-md` (denser than the full Certifications-page grid, since this is a secondary region on a product page, not the page's main content) — or a horizontal scroll strip on mobile if more than 3 certs apply to one product (planner's call, consistent with "long list → card grid/strip, not `<ul>`" taste guidance).
- Halal elevation/badge treatment inherited verbatim from Phase 2's CertCard — **no changes to CertCard's component code**, only new call-sites.
- Zero applicable certifications: region omitted entirely (no "no certifications" empty state needed here — absence of certs on one product is not itself noteworthy the way an empty catalog section would be).
